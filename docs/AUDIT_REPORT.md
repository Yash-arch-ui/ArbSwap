## 1. Executive summary

1. **The Rust/Anchor core is real and green.** `cargo test --workspace` (27 tests), `anchor build`, `pytest research -q` (103 tests) and the LiteSVM lifecycle all pass. `update_quote`, `swap`, deposit/withdraw and the breaker have genuine on-chain guard logic and per-instruction tests.
2. **The headline P1 result (`docs/P1_RESULTS.md`, the W1–W6 pre-registered study) is not reproducible.** It is generated by `research/sim/study.py`, which is **untracked and not in git**, its JSON artifacts directory `research/data/results/` **does not exist**, and the S2 phase in that file is **broken** (returns a tuple). `python -m research.sim.study render` exits 1. **CRITICAL.**
3. **The P3 keeper is numerically wrong for SOL/USDC.** `q_bps = (B*P − Q)·10⁴/(B*P + Q)` mixes SOL base amounts (9 decimals) with USDC quote amounts (6 decimals) with no scale normalisation, so the inventory skew is off by ~10³×. The parity test only uses same-scale fixtures, so it does not catch this. **HIGH.**
4. **The on-chain keeper is not bounded in the parameter that matters.** `swap` executes the **keeper-supplied `levels`**; the only checks are shape (`sqrt_lo < sqrt_hi`, `liquidity > 0`). `max_anchor_step_bps` constrains a *different* field (`anchor_sqrt_price`) that the swap never reads, `ask_extra_bps`/`bid_extra_bps` are unbounded, and `max_inventory_bps` is stored but never used. A malicious keeper can quote arbitrarily. **HIGH.**
5. **The "cheap update" claim is not supported.** Measured `update_quote` = **12,802 CU**, ~19–26× the paper's 485–676 CU propAMM median; `swap` = **201,119 CU**, above the 200,000 transaction default and ~12× the paper's ≥16,938 CU swap floor.
6. **Several documents contradict the code** (stale `docs/FORMULA.md` status table, `trip_breaker` 7,051 vs measured **10,051**, `max_staleness_slots` vs `_seconds`, README gives no P1 reproduction command).
7. **No secrets are committed.** `.ENV` is gitignored and was never tracked; no keypair/`id.json`/PEM is tracked; the Pyth key is read from env. **INFO — clean.**
8. The simulator's causality (no look-ahead), USDT→USDC conversion, latency/noise/landing-delay/gas modelling and the walk-forward split for `report.py` are genuinely present and tested. The simulator is the strongest part of the repo.
9. **Real, honestly-reported losing results exist**: the synthetic-regime P1 tables show ArbSwap losing to B1 on E1 in calm/trend/crash; the code and docs say so.
10. **Verdict:** ready for local-validator testing; **not** ready for devnet-with-funds, P4 charts, or demo day (see §9).

### 4.4 Golden vectors

- **Count:** 970 cases (+1 header line) — `wc -l golden_vectors.txt` → 971. `golden.rs` asserts `checked >= 500`.
- **Categories (from column 1):** `mul_q64`, `div_q64`, `sqrt_q64`, `recip_q64`, `price_from_sqrt`, `one_plus_q64`, `sqrt_price_scaled`, `mul_bps`, `ceil_bps`, `tdiv`, `walk_ask`, `walk_bid`, `first_deposit`, `deposit_shares`, `withdrawal`, `fee`.
- **Edge cases:** generator (`research/reference/golden.py`) includes **zero/one amounts** (e.g. `walk_bid|…|amount=0|expected=0`, `sqrt_q64 v=0`, `fee amount small`), the **`recip_q64` domain guard `s>=2`**, `one_plus_q64` signed boundary `x ∈ [−9000,9000]`, and **floor-vs-ceil pairs** (`mul_bps`/`ceil_bps`). It does **not** include an explicit `u128::MAX` overflow-boundary vector (overflow is covered instead by `properties.rs::overflow_is_checked` via `mul_div_floor(u128::MAX,2,1)`), and **no explicit "rounding tie" vector** (ties are covered probabilistically by `bps_rounding_directions_are_exact` over 5,000 samples).
- **Truly independent?** **No — and this is important.** `research/reference/ladder.py` states in its docstring: *"Mirrors `crates/arb-math/src/quote.rs` bit-for-bit."* The Rust `quote.rs` header says it "mirror[s] the Section 5 formulas". `golden.py` imports from `reference.fixed`/`reference.ladder` (the mirror), **not** from the independent float `quote_math.py`. So the golden test is a strong **differential regression check between two languages of the same algorithm**, not proof that the algorithm is correct. The *independent* float implementation (`quote_math.py`) is exercised separately by `test_quote_math.py` (11 tests) against the same formulas. **Finding F-07.**

- **Exists (9 in `crates/arb-math/tests/properties.rs`):** exact-floor sqrt (2,000 samples), `mul_q64` bound, reciprocal floor inverse, ask/bid walk monotonicity + capacity bound, round-trip no value creation, exhausted capacity reports remainder, bps rounding, repeated round-trips cannot grow quote. Deterministic LCG, no external deps.

- **Missing:** no `cargo-fuzz`/`proptest` harness; no property test that the **program**'s inline deposit/claim math equals `arb-math`'s `first_deposit_shares`/`withdrawal_amounts` (the program re-implements `integer_sqrt` and does the division inline — `lib.rs::integer_sqrt`), so a drift between the two is not caught by a property test.

### 4.6 Keeper parity — specific gaps

`research/sim/test_keeper_parity.py` re-implements the expected quote in Python and asserts equality with `cargo run -p arbswap-keeper -- single`. However:

- `expected()` returns `"spread": 1` and `"depth": 10_000` **hard-coded**, which are exactly the keeper's σ=0 outputs (`spread_floor_bps=1`, `depth=BPS`). The test never exercises a non-zero-volatility spread or a throttled depth.
- `expected()` hard-codes `inventory_coeff = 5` (the keeper default); it is not parameterized.
- All three fixtures use `base`/`quote` on the **same scale** (`1000/150000`, `2000/246000`, `900/120000`), so it cannot catch the real SOL(9)/USDC(6) decimals bug (F-03).
- The keeper's spread formula differs structurally from `quote_math.compute_half_spread` (no `spread_min` clamp, no directional add-on, no `confidence_max` cutoff, no jump cooldown), and the keeper encoder writes `ask_extra_bps = bid_extra_bps = 0` (`keeper/src/lib.rs::encode_update_quote_instruction`). So **the on-chain path never sees the directional add-on** described in `MATH.md §5`.

## 6. Simulator and results audit

### 6.1 Look-ahead (the most important check)

- **Test:** `research/sim/test_causality.py::test_quote_live_at_t_ignores_reference_after_t_minus_latency` builds two worlds that agree until `t=diverge` then differ, and asserts `a[:diverge+latency] == b[:diverge+latency]` (byte-identical) **and** that they diverge afterwards (non-vacuous). Also `test_future_prices_change_results_and_removal_restores_them` (shuffled-future): a clairvoyant oracle moves PnL; switching it off reproduces the honest run exactly.
- **Mechanism:** `engine.simulate` resolves `reference = prices[src_idx]` (current) and `stale_price = prices[stale_idx]` with `stale_idx = _source_index(now − (latency − cheat))`; `oracle.sample` only draws noise when `publication_index` advances. The vault's quote therefore depends only on data at `≤ t − latency`.
- **Verdict: PASSED.** No look-ahead found. This is the single strongest piece of evidence in the repo.

### 6.3 Runs, regimes, and tuning discipline

- `research/sim/report.py` (committed, reproducible) builds **synthetic** GBM regimes (calm 0.35, trend 0.7, crash 2.0 annual vol) and optionally a real CSV; calibration is a **2-fold walk-forward** grid (81 candidates) frozen before the held-out segment. A real-data section is included when `--real` is passed.
- `research/sim/study.py` (untracked) is the **pre-registered 6-week** study: `W1` calibration only; `W2–W6` held out; regime labels assigned mechanically; S1–S5 sensitivity studies. **The committed `docs/P1_RESULTS.md` is this study's output.**
- **Tuning discipline:** for `report.py`, walk-forward — parameters chosen on an earlier fold, evaluated on a later fold. For the committed `study.py` output, the pre-registration text in `docs/P1_RESULTS.md` **explicitly fixes** the clock, seed, grid, blocks, and tie-break *before* running; this is a strong protocol — **but it cannot be verified** because the generator and artifacts are missing (F-01).

### 6.4 Results per regime — including losing/mixed cases

**Synthetic regimes (`docs/P1_RESULTS.md` committed content, E1 = ArbSwap vs B1):** calm **−101.36%**, trend **−101.74%**, crash **−99.70%**. The vault *loses to B1* on E1 in all three synthetic regimes; the doc reports this openly. E9 sensitivity (calm) shows every variant still below B1 (`−98.9%` to `−109.2%`).

**Real-data sample replay (`docs/P1_RESULTS.md` real section, Binance SOLUSDC 1s):** E1 = **+100.00%** in all three labelled windows. **Cause analysis:** B1's markout is catastrophically negative there (`−26 bps`), i.e. B1 is picked off far worse than the vault; the "+100%" is almost entirely B1 blowing up, not a vault win on level terms. The vault's absolute hedged PnL in that section is **≈0** (calm `0.0`, trend `0.2`, crash `0.0`) versus B1 `≈ −1,760`. **This is a mixed/misleading result and the report does not foreground the cause.**

**Metrics present per venue (both sections):** hedged PnL, 2 s markout, quiet half-spread, quote-vs-fill gap, trades, rejects, fill rate, turnover, keeper updates, update gas/priority, cost per update, recorded swap cost, theory LVR.

**Sensitivity:** S1 clock (1.0/0.1 s), S2 slot (0.4/0.6/1.0 s), S3 oracle latency (0.05/0.2/0.4/1.0 s on a 100 ms aggTrades reference), S4 seeds (5), S5 regime mix — **all defined in `study.py`, none reproducible** (artifacts missing; S3 needs aggTrades CSVs that are absent: `ls research/data/raw | grep agg` → none).
