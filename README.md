## Reproducing the P1 held-out study

`docs/P1_RESULTS.md` is generated by the pre-registered study runner. The
windows, clock, calibration grid/blocks, metrics and studies are fixed in
`research/sim/windows.py` *before* any run; the phases below each write an
artifact under `research/data/results/`, so a crash never costs a finished
phase.

```bash
# Raw inputs (gitignored): two 6-week 1-second archives, plus 3 aggTrades days
python -m research.data.download_vision --kind klines --symbol SOLUSDT \
    --start 2026-08-24 --days 42 --out research/data/raw/binance_SOLUSDT_1s_6w.csv
python -m research.data.download_vision --kind klines --symbol USDCUSDT \
    --start 2026-08-24 --days 42 --out research/data/raw/binance_USDCUSDT_1s_6w.csv
for d in 2026-09-10 2026-09-17 2026-10-01; do
  python -m research.data.download_vision --kind aggtrades --symbol SOLUSDT \
      --dates "$d" --bin-ms 100 \
      --out "research/data/raw/binance_SOLUSDT_aggtrades_100ms_${d}.csv"
done

# W1 calibration -> W2-W6 held-out -> studies S1-S5 -> docs/P1_RESULTS.md
python -m research.sim.study calibrate
python -m research.sim.study evaluate
python -m research.sim.study studies
python -m research.sim.study render
```

`python -m research.sim.report` is a separate *synthetic/exploratory* generator
and writes `docs/P1_SYNTHETIC.md`, so it can never overwrite the pre-registered
`docs/P1_RESULTS.md`.

## Ground rules (Build Plan §0)

Python is an independent high-precision reference and generates golden vectors;
Rust `arb-math` is the production integer path used by the on-chain ladder and
keeper. No floats are used on-chain; rounding favors the vault; security is over
speed; never claim an unmeasured result; report losing regimes.
